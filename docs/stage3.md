# Етап 3 — інтеграція Cal.com

**Статус:** публічну адресу типу події вже підключено: **https://cal.com/bogdan-n-usjpw6/consultation**. Потрібно виконати перевірку доступності, реального бронювання та Google Calendar.

## 1. Налаштуйте Cal.com

1. Створіть особистий акаунт на [Cal.com](https://cal.com/) або у європейському регіоні Cal.eu.
2. У `Event Types` створіть **один** тип події (наприклад «Первинний брифінг»).
3. Вкажіть тривалість **45 хвилин**, якщо підтверджуєте тестовий текст сайту. Налаштуйте робочі години, часовий пояс **Europe/Kyiv**, мінімальний термін до початку та кількість бронювань в одному слоті.
4. У `Booking Questions` залиште ім’я, email і додайте телефон (за потреби зробіть обов'язковим). Якщо потрібен вибір офлайн/онлайн, налаштуйте відповідне питання або доступні локації у Cal.com. **Сайт не створює форму самостійно.**
5. Підключіть Google Calendar: календар призначення для записів і календарі, за якими перевіряється зайнятість. Проведіть окремий тест блокування часу.
6. Налаштуйте автоматичні підтвердження та перевірте правила перенесення/скасування. Не публікуйте сайт до перевірки реального бронювання.
7. Скопіюйте **публічне посилання конкретного типу події**, а не URL адмінпанелі. Приклади: `https://cal.com/your-username/45min` або `https://cal.eu/your-username/45min`.

Офіційні джерела: [Cal.com Embed](https://cal.com/embed), [Cal.com FAQ](https://cal.com/faq), [питання бронювання](https://cal.com/blog/customize-your-scheduling-environment-a-guide-to-cal-com-s-booking-questions).

## 2. Активуйте вбудований календар на сайті

Відкрийте `public/assets/js/booking-config.js`:

```js
window.KTAWF_BOOKING = Object.freeze({
  eventUrl: "https://cal.com/bogdan-n-usjpw6/consultation", // вже налаштоване посилання
  theme: "light",
  brandColor: "#25382e",
});
```

Посилання вже налаштоване: змінювати HTML **не потрібно**.

- Якщо `eventUrl` порожній, сайт показує інформаційний статус, а **не** фальшивий календар.
- Якщо URL коректний, вбудований календар Cal.com відкривається безпосередньо у секції `#booking`.
- Поруч є пряме посилання на цю ж сторінку Cal.com для випадків, коли сторонній віджет не завантажився.
- Скрипти стороннього сервісу завантажуються **лише після** налаштування дійсної адреси.
- Підтримуються офіційні домени `cal.com`, `app.cal.com`, `cal.eu`, `app.cal.eu` для типу події.
- **Жодних API-ключів, секретів, токенів або паролів у `booking-config.js`.**

## 3. Архітектура інтеграції

```text
public/index.html (#booking)
    ├── #booking-status  — повідомлення про налаштування/завантаження/помилку
    ├── #cal-inline      — Cal.com Inline Embed (календар, форма, підтвердження)
    └── #booking-open-link — пряме посилання на ту саму подію

public/assets/js/booking-config.js — публічний URL події та кольори
public/assets/js/booking.js        — парсинг URL, завантаження офіційного Embed SDK
Cal.com                         — вільні слоти, перевірка конфліктів, заявки
Google Calendar                 — пов'язані календарні події та зайнятість
```

Cal.com відповідає за дані запису, часові слоти, створення, перенесення, скасування та повідомлення. Сайт не зберігає персональних даних клієнтів і не намагається обчислювати доступність своїм JavaScript.

## 4. Перевірка перед запуском

1. Подія вже доступна за адресою `https://cal.com/bogdan-n-usjpw6/consultation`. Перед тестом перевірте налаштування конкретної події: тривалість, графік та питання. Запустіть локально `python3 -m http.server 8000 --directory public`.
2. Виконайте `python3 tests/smoke.py` та `node tests/booking-node.js`.
3. Переконайтесь, що в Cal.com обрано потрібний часовий пояс, календар правильно показує майбутні дати, а поле телефону працює.
4. Створіть **тестове реальне бронювання**, перевірте його у Cal.com і Google Calendar. Потім скасуйте.
5. Перевірте, що друге бронювання того самого часу неможливе.
6. Перевірте скасування, перенесення, підтвердження електронною поштою, блокування часу подіями з Google Calendar.
7. Перевірте віджет на мобільних і настільних браузерах. Резервне посилання має вести до тієї самої події.
8. За потреби налаштуйте CSP із дозволами для домену вашого регіону Cal.com. Не встановлюйте надмірно сувору CSP до перевірки роботи віджета.
9. Відредагуйте `privacy.html` під реального власника сайту й фактичну обробку персональних даних **до прийому бронювань**.

> Юридичне застереження: `privacy.html` досі є шаблоном, тому інтеграція не означає готовності сайту до реального публічного прийому персональних даних.

## 5. Обмеження й режими відмови

- Якщо посилання на тип події буде видалено з конфігурації, **календар буде вимкнено** й сайт не показуватиме фіктивної доступності.
- Локальний тест із мокованим Embed SDK перевіряє правильність інтеграційних викликів, але **не підтверджує реальних вільних слотів чи створення записів**.
- При помилці мережі віджет може не відкритися; прямий URL і контакти залишаються доступними.
- Для аккаунта Cal.eu скрипт завантажується з `app.cal.eu`, для Cal.com — з `app.cal.com`.
- Параметри, введені в Cal.com (графік, тривалість і питання), не керуються кодом сайту.
