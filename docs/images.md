# Графические ресурсы сайта

Проект использует **семь фиксированных путей**. Все семь изображений из загруженного `kkk.zip` уже добавлены в `public/` и подключены в HTML. Фотографии считаются иллюстративными до подтверждения их соответствия реальным объектам компании.

Для замены достаточно **перезаписать соответствующий файл с тем же именем**. Не надо изменять HTML, CSS, JavaScript или запускать сборку. Исключение — одноразовая настройка домена для `og:image`, описанная ниже.

| Файл (от корня сайта) | Рекомендуемый размер | Формат | Назначение |
|---|---:|---|---|
| `public/assets/images/hero-art.webp` | **1320 × 1480 px** | WebP | Основная фотография первого экрана, желательно вертикальная; важное — ближе к центру. |
| `public/assets/images/gallery-01.webp` | **1200 × 1600 px** | WebP | Галерея: интерьер / общее пространство. |
| `public/assets/images/gallery-02.webp` | **1200 × 1600 px** | WebP | Галерея: атмосфера / рабочая зона. |
| `public/assets/images/gallery-03.webp` | **1200 × 1600 px** | WebP | Галерея: деталь / особенность компании. |
| `public/assets/images/logo.svg` | **240 × 80** (пропорция 3:1) | SVG | Логотип в шапке, футере, на странице политики и 404. |
| `public/favicon.svg` | **64 × 64** (квадрат, вектор) | SVG | Значок вкладки браузера. |
| `public/assets/images/og-image.jpg` | **1200 × 630 px** | JPEG | Превью ссылки для Telegram, Facebook и других соцсетей/мессенджеров. |

## Как заменить изображения

1. Подготовьте четыре фото и экспортируйте в **WebP**, используя имена из таблицы (регистр букв важен).
2. Положите их в `public/assets/images/` вместо установленных сейчас изображений.
3. Замените SVG логотипа и favicon своим фирменным знаком; в идеале сохранить указанную пропорцию (обратите внимание на читаемость на светлом и тёмном фоне).
4. Подготовьте и замените `og-image.jpg`: на нём должны быть разборчивые логотип/название/изображение, с запасом по краям.
5. **Один раз, после назначения домена** замените `https://example.com` внутри `public/index.html` в метатеге `og:image` на настоящий HTTPS-домен, например `https://your-site.ua/assets/images/og-image.jpg`. Соцсети обычно не выполняют JavaScript, относительный URL здесь не подходит.
6. Обновите текстовые подписи `alt` в `public/index.html`, чтобы они описывали **реальные** фото. Изменение alt требуется при замене *содержания* картинки, но не для загрузки файла.
7. Выполните `python3 tests/smoke.py` и откройте сайт на телефоне и ПК.

Изображение `og-image.jpg` — **отдельный файл**. При замене hero-фотографии OG-превью автоматически не пересоздаётся.

## Компоновка / обрезка

- **Hero:** исходная пропорция 1320:1480 (почти 9:10). На ПК изображение заполняет правую колонку; на планшете и телефоне пропорция области меняется.
- **Галерея:** исходная пропорция 3:4. На ПК область близка к 3:4, на планшете изображения становятся шире, поэтому часть сверху/снизу обрежется.
- Используется `object-fit: cover`: **картинка не растягивается и не искажается**, но часть фотографии может быть обрезана.
- Держите главный объект **не у края**. Не вписывайте текст в изображения: он может попасть под обрезку.
- При необходимости изменить фокус: в `public/assets/css/site.css` можно указать `--hero-image-position` или `--gallery-image-position` (обычно `center center`). Пример:

```css
.hero__visual { --hero-image-position: 55% 35%; }
.gallery-card:nth-child(2) { --gallery-image-position: 60% 40%; }
```

## Практические ограничения

- Для WebP обычно подходит качество **75–85**. Целевой размер одной фотографии — примерно 100–350 КБ; зависит от сложности изображения. Размеры из таблицы — рекомендуемые, сайт выдержит изображения другого разрешения, но большие файлы будут грузиться медленнее.
- Картинки в галерее загружаются отложенно; hero запрашивается с повышенным приоритетом.
- Для предоставленного логотипа используется **тёмная подложка в светлой шапке сайта**, поскольку его буквы белые. В футере логотип отображается в исходных цветах без фильтра.
- Если логотип имеет существенно другую пропорцию, потребуется один раз изменить CSS `.brand__logo` (`width`/`height`), но **пути и HTML не меняются**.
- Размеры `width` и `height` в HTML соответствуют рекомендуемым пропорциям и уменьшают скачки макета. При использовании других размеров сохраняйте соотношение сторон или исправьте эти атрибуты.
- Старые векторные иллюстрации удалены после импорта файлов из `kkk.zip`.
- SVG-файлы, полученные от третьих лиц, желательно проверить на отсутствие встроенного JavaScript и посторонних ссылок.

## Імпорт готових зображень із `kkk.zip`

У вихідному архіві **`hero-art.svg` та `gallery-01.svg`–`gallery-03.svg` насправді містять JPEG-дані**, а не векторні SVG. Їх перетворено на оптимізовані файли WebP із розмірами з таблиці вище. Оригінали не входять до дистрибутива сайту — вони залишаються у вихідному архіві користувача.

- `logo.svg` та `favicon.svg` скопійовані без зміни вмісту.
- `og-image.jpg` масштабовано та обрізано під 1200 × 630 px без спотворення пропорцій.
- Для нового світлого дизайну шапки логотип із білими літерами отримав темну підкладку; у футері збережено оригінальні кольори логотипу.
- Альтернативні підписи `alt` залишено відповідно до вмісту зображень (ситуаційний центр, робоча зона, спорядження).
- На етапі 3 інтеграція Cal.com не потребує додаткової обробки цих зображень.
